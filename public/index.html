        💡 Web / Subsonic 评分说明

        星级评分与爱心收藏独立，两端共用评分。Web 支持歌曲评分；Subsonic 还可为歌手、专辑评分（取决于客户端）。低分转不喜欢与不喜欢补评分分别由开关控制，不喜欢自动补分由各用户在 Web 设置 → 逻辑中单独开启，默认关闭；后台补分独立执行，不受用户开关和低分阈值影响。

        本地歌曲未关联时使用本地评分；关联后以在线歌曲评分为准，与在线版及其他关联副本共用。在线版已有评分时保留在线评分并删除本地评分；仅本地有评分时迁移到在线 ID，同时保留评分来源与记录。

        联动只补数据，不撤销历史：调低阈值、提高或清除评分、关闭开关均不会删除已有规则。需要处理历史数据时，可预览补齐或按阈值重算。重算仅撤销可追溯的评分联动原因，手动与来源不明规则保留。

        了解哪些文件会备份、哪些目录排除，以及恢复时如何处理同名文件

        先选范围，再启用并保存服务

        在“备份管理 → 云端备份 → 备份范围”勾选 WebDAV 列并保存。勾选“歌曲与歌词”后，WebDAV 可以备份歌曲；并非只备份配置和歌单。选择范围不等于已启用服务，执行云端备份还需要有效连接和已保存的启用状态。

        歌曲与缓存：默认目录示例

        下面以程序运行目录为基准，假设 DATA_PATH 使用默认的 data/：

        位置 常规数据备份
        cache/ 不备份：程序运行目录的缓存。
        music/ 不备份：程序运行目录中独立的音乐目录，不是默认的数据音乐目录。
        data/cache/ 不备份：数据目录中的播放缓存。
        data/users/用户/cache/ 不备份：用户目录中的缓存，其他层级的 cache 目录同样排除。
        data/music/ 可以备份：需勾选并保存“歌曲与歌词”；包含音频、已有 LRC、封面及音乐索引。
        外部自定义曲库，如 D:/音乐/ 不备份：需另行保存该曲库。

        自定义路径：修改 DATA_PATH 后，以实际数据目录为准。例如数据目录是 D:/LXData，歌曲范围就是 D:/LXData/music；如果数据目录直接设为程序运行目录，运行目录的 music/ 就可被选中备份。缓存、日志、runtime、临时文件、本地备份包和工作数据库仍排除，目录链接不会被跟随。

        OpenList 播放缓存是例外的独立功能：可按用户规则上传播放缓存，甚至在严格校验后删除本地缓存；这里的 WebDAV/常规数据备份不会因为开启该功能就包含 cache。

        增量文件备份：本地 → 云端

        定时备份对比本地内容指纹与成功记录，上传新增或变化的所选文件；“同步所有文件”会重新上传当前所选范围内的本地文件。保存到配置的增量目录，默认 /lx-sync，保留相对目录结构。不会自动下载云端更新，也不是双向实时同步。

        ZIP 历史备份：本地 → 云端

        按相同的已保存范围打包，不是把整个 data 无条件打包。归档上传到 ZIP 目录，默认 /lx-sync-backups。成功上传后按保留份数/天数清理历史，始终保留最新一份。

        恢复：云端 → 当前服务器

        打开“数据恢复 → WebDAV”，选择增量目录或指定 ZIP，再选择覆盖方式。先预览新增、覆盖、合并索引和跳过数量，确认后执行。ZIP 预览需要下载整个归档，执行时复用。

        • 仅补缺失文件：已有文件保留，只补本地没有的内容；必要的音乐/快照索引按条目合并。
        • 覆盖同名文件：所选范围的同名文件以备份为准，本地独有文件保留。不会自动判断哪一端更新，普通 JSON 不按字段合并。
        • 安全与生效：全部待写入文件暂存校验后再替换，写入失败尝试回滚；建议保留恢复前副本。手动恢复后需重启服务，刷新网页不等于重新加载数据。

        本地 ZIP、删除同步与启动恢复

        • 本地离线 ZIP：无需启用 WebDAV，也使用 WebDAV 列已保存的数据范围。在“本地备份”导出，在“数据恢复 → 本地 ZIP”导入；不会上传云端。
        • 关闭某个备份类型：停止后续备份该类内容，不清理已有云端副本。
        • 删除同步：默认关闭，本地删除后保留云端副本；显式开启后，下次增量备份删除已跟踪的对应云端文件，不影响 ZIP 历史。
        • 启动恢复：默认关闭；显式开启后每次启动先用云端所选数据覆盖本地，再开放服务，不限于空目录首次启动。
        • 校验流量：普通上传检查响应与远端大小，不自动下载歌曲全文验证；恢复随必要下载核对可用的 SHA-256 清单，旧备份无清单时仅检查大小并提示。

        OpenList 使用场景与原理

        区分常规数据备份、用户播放缓存、内容校验和数据恢复

        开始前：连接、启用和保存是三件事

        先在 OpenList 自己的存储管理中配置可用挂载，再填写这里的服务器地址、令牌和备份根路径。根路径是 OpenList 网页内的路径，例如 /local，不是 Windows 磁盘路径。测试连接只读取目录，不保存配置，也不验证全部写入和删除能力。启用并保存后，后台才按已保存周期执行。

        常规数据备份：本地 → OpenList

        使用“备份范围”中 OpenList 列已保存的五类选择：歌曲与歌词、用户音源、歌单与不喜欢快照、用户数据、系统与账户。保存到 备份根路径/_data/相对路径，例如 /local/_data/music/用户/歌曲.mp3。不会上传后删除本地；关闭范围不会清理已有云端副本，本地删除也不会自动传播到该数据目录。

        播放缓存：按用户独立处理

        下方“OpenList 播放缓存”卡片单独选择用户和模式，云端位置为 备份根路径/用户名/cache/，例如 /local/admin/cache/。常规数据备份排除 cache，不代表高级用户缓存规则不能上传缓存。两套范围与保存按钮互相独立。

        具体读取本地哪个目录？

        常规“歌曲与歌词”读取实际数据目录的 music/，默认 data/music/，包含已有 LRC、封面与索引。排除数据目录外独立的根目录 music/、各级 cache、外部自定义曲库、日志、runtime、临时文件和本地备份包。自定义 DATA_PATH 后以实际数据目录为准。

        高级播放缓存跟随该用户当前缓存位置：data 对应 数据目录/cache/用户名/，root 对应 程序运行目录/cache/用户名/，不是同时扫描两边。用户未设置时使用全局位置；旧配置中有效的自定义 cacheDir 优先沿用。

        四种缓存模式不是一次性操作

        选择后点击“保存播放缓存设置”才生效；需要 OpenList 已启用并保存、用户规则已启用。“立即备份并同步缓存”只是提前执行一轮，自动同步间隔默认 60 分钟，后台检查与失败重试默认 5 分钟。

        模式 执行方式与注意事项
        上传，保留本地 新缓存写入可触发上传；已有缓存由定时同步或手动同步处理，保留本地副本。
        上传并校验后删除本地 音频与已登记附件通过严格内容校验、确认本地未变化后才删除。保存此规则就可能开始处理已有缓存，不一定等你点击立即同步。 校验失败保留本地，可能消耗云端下载流量。
        从 OpenList 下载到本地 定时或手动同步从用户对应的云端目录下载；不反向上传新本地缓存。它处理用户缓存，不等同于恢复配置、账户或歌单。
        本地与 OpenList 双向同步 定时或手动处理两个方向，新缓存可触发上传；存在差异时按记录与文件状态判断，并非普通 JSON 的字段合并。涉及删除传播和冲突处理，需要保留独立备份，不能当成只增不减的归档。

        上传完成 ≠ 内容已经完整校验

        普通上传检查成功响应、远端存在与大小，不自动下载整首歌曲验证。需要时在“记录与校验 → OpenList → 内容校验”先统计流量，再手动启动。存储能提供有效 SHA-256 时比较摘要，否则流式读取云端正文；校验只报告结果，不自动修复。上传后删除本地缓存仍需严格校验。

        “缓存上传时附带已有的封面与歌词”只影响高级缓存规则，不会自动下载缺少的歌词或封面，也不会从普通 music 数据备份中排除 LRC。

        想恢复配置、歌单或歌曲？使用数据恢复

        进入“数据恢复 → OpenList”，选择当前备份或可用历史版本，选择仅补缺失或覆盖同名，扫描预览后确认。普通 JSON 不按字段合并，本地独有文件保留。所有待写入文件先暂存校验，再提交；失败尝试回滚。建议保留恢复前副本，手动恢复完成后重启服务。

        每次成功备份可保存恢复清单及去重历史内容，额外占用存储。按“云端历史版本保留天数”清理过期历史对象，不删除当前数据和播放缓存；历史版本不能替代独立存储的备份。

        允许作为播放来源，是另一个独立开关

        开启备份不会自动启用云端播放。Web 还需开启服务器已有歌曲优先；Subsonic 需开启自己的缓存优先与 OpenList 选项。系统按当前用户及已登记的缓存/下载记录查询，在本地未命中后尝试云端，不逐首扫描整个网盘。普通 _data 备份不会自动变成云端音乐目录。
