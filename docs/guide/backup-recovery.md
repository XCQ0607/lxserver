# 云端备份与恢复

在后台「系统设置 → 云端备份范围」中，按数据类型分别选择 WebDAV 和 OpenList。两列互相独立：同时勾选表示保存两份副本，不会在两个云端之间同步。服务连接和自动执行仍由各后端的启用开关控制。

## 哪些内容会备份

| 类型 | 文件范围 | 恢复位置 |
| --- | --- | --- |
| 歌曲与歌词 `music` | `data/music/**`，包括歌曲、歌词、封面、`music_index.json` | 当前实例的 `data/music`，保留相对目录 |
| 用户音源文件 `userFiles` | `data/users/source/**`、`data/source/**`、`data/uploads/**` | 当前实例的同名相对目录 |
| 快照 `snapshots` | 用户歌单和不喜欢列表的快照正文及 `snapshotInfo.json`；包括无扩展名文件 | 原相对目录；外部歌单快照按本机 `snapshot.backupPath` 定位 |
| 用户数据 `userData` | `data/users/<用户目录>/**` 中除音源、快照及临时文件之外的数据 | 保留用户目录名及相对路径 |
| 系统与账户 `system` | `config.js`、数据目录根部的 JSON 文件，如 `users.json`、`serverInfo.json` | 配置恢复到当前 `CONFIG_PATH`；JSON 恢复到当前数据目录 |

`cache`、`runtime`、日志、临时文件、SQLite 工作库/WAL、已有本地备份包始终排除。不会跟随目录联接或符号链接，不会备份外部自定义音乐目录。歌曲备份不是整个服务器磁盘备份。

用户目录名称包含账户标识，恢复时需要保留名称。歌曲索引与音频归在同一类，避免只恢复索引而没有对应音频。系统和用户数据可能包含密码、令牌或设备信息，请使用自己控制的云端目录。

## 写入 config.js 的设置

```js
module.exports = {
  'backup.webdav.types': ['music', 'userFiles', 'snapshots', 'userData', 'system'],
  'backup.openlist.types': ['music', 'userFiles', 'snapshots', 'userData', 'system'],
  'backup.webdav.mirrorDeletes': false,
  'backup.webdav.restoreOnStartup': false,
}
```

类型数组允许为空，表示该目的地不备份任何数据类型。后台保存时校验类型并写入实际使用的配置文件。取消勾选只改变之后的备份和恢复范围，不会删除云端已有文件。

`webdav.excludeCache`、`webdav.excludeMusic` 保留旧配置兼容接口。新的类型数组是范围选择的依据；缓存现在固定排除，不再提供相互冲突的界面开关。旧 `openlist.backupSystemConfig` 只用于未采用新类型设置的旧流程，不再作为新界面的第二个系统备份开关。

## 两种云端的执行方式

WebDAV 增量备份将所选文件按相对路径保存到 `webdav.syncPath`；ZIP 备份将相同范围打包保存到 `webdav.backupPath`。它们分别维护成功基线，增量上传不会让 ZIP 误判为没有变化，失败上传也会在下一轮重试。

本地离线 ZIP 导出和导入复用 WebDAV 列已保存的范围，但无需启用 WebDAV，也不会访问云端。界面会明确说明这个范围，避免把部分导出误认为整个服务器的全量副本。本地配置每日历史副本仍由 `configBackup.*` 管理；它只保存配置，不替代上述数据备份。

默认保留已上传的散文件，即使本地已经删除。只有显式打开 `backup.webdav.mirrorDeletes`，本地删除才会传播到散文件目录。镜像删除不会更改历史 ZIP。两种定时任务和恢复操作不会在同一个 WebDAV 实例内同时运行。

OpenList 数据备份保存在 `<openlist.root>/_data/<相对路径>`，默认只上传并保留本地文件。同步间隔由 `openlist.syncInterval` 控制；「立即备份 / 同步缓存」也会执行一次。SQLite 记录用于显示进度及重试，不是恢复的唯一依据：新实例没有旧数据库，也能枚举 `_data` 恢复文件。

OpenList 高级永久播放缓存使用独立的用户规则和目录。它可以上传 `cache`、上传后清本地或用于 Subsonic 直链/代理交付，**不属于上面的数据备份范围**，默认不会因为勾选「歌曲与歌词」而启用。新界面的歌曲、快照、系统备份不再由这些用户缓存规则重复控制。

上传后清理播放缓存之前会核对远端真实内容的 SHA-256；这一步需要从远端读取音频，会增加一次校验流量。本地在传输期间发生变化时保留文件。普通数据备份没有上传后删除行为。

## 恢复步骤

1. 在目标实例配置云端连接，确认数据目录、`CONFIG_PATH` 和外部快照挂载位置。
2. 在系统设置中选择要恢复的类型并保存。外部快照必须先设置本机的 `snapshot.backupPath`；不会直接采用云端提供的绝对路径。
3. WebDAV 选择散文件或指定 ZIP 恢复；OpenList 使用「恢复所选数据类型」。两者都只下载所选内容，覆盖同名文件，保留本地独有文件，不反向上传。
4. 检查返回结果和日志。恢复过程使用临时文件后重命名，截断下载不会覆盖原文件。多个文件的恢复不是一个原子事务，部分失败时应检查失败列表后重试。
5. 重启服务后，重新加载用户、歌单、音源和音乐索引。仅刷新网页不能刷新所有服务端内存状态。

WebDAV 启动恢复默认关闭。确需无人工干预的灾备启动时可设置 `backup.webdav.restoreOnStartup=true`；这会按已保存范围覆盖同名本地文件。自动模式只在散文件目录不存在或没有所选文件时尝试 ZIP，不会把认证或网络故障解释成“云端为空”，也不会在恢复失败后自动上传本地数据。

旧 ZIP 中即使存在缓存，恢复仍按当前类型过滤。旧 OpenList 按用户存储的音频可继续由兼容缓存流程访问；新的统一恢复入口读取 `_data`，不猜测或移动旧目录。

## 验证边界

回归测试覆盖真实 SQLite、本地 HTTP OpenList 测试服务、WebDAV 客户端替身、ZIP 打包/恢复、全新目录恢复、类型过滤、缓存排除、上传失败重试及部分音频交付行为。这些检查不代表所有云盘挂载、真实 WebDAV 服务和真实 Subsonic 客户端都已实测。首次使用时应先备份少量文件，并在独立空目录验证恢复结果。
