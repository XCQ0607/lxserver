# 备份与恢复

要防止误删歌单、服务器损坏或迁移时丢失数据，先选择备份内容，再选择保存位置。可以只保存在本机，也可以使用 WebDAV、OpenList 保存云端副本。两种云端独立工作，同时启用会保存两份，不会互相同步。

## 先选适合你的方式

| 需要做什么 | 使用什么功能 |
| --- | --- |
| 找回以前的歌单或不喜欢列表 | 歌单、不喜欢列表的历史快照 |
| 找回以前的服务器设置 | 本地配置历史备份 |
| 下载一份数据留存或迁移 | 备份管理中的本地 ZIP 导出、导入 |
| 自动把数据复制到网盘 | WebDAV 或 OpenList 数据备份 |
| 把播放缓存上传到 OpenList，或上传后节省本地空间 | OpenList 的高级用户播放缓存规则，需单独配置 |

配置历史备份只保存配置，不包含全部用户数据和歌曲。歌单快照也不包含音频文件。需要恢复整套数据时，应选择对应的数据备份范围，并单独保管未纳入范围的外部音乐目录。

## 哪些内容会备份

在后台 **备份管理 → 云端备份 → 备份范围** 分别选择 WebDAV 和 OpenList 的内容，保存后生效。每一列独立选择；全部关闭表示该端不备份这些数据，但不会删除已经上传的文件。

| 界面选项 | 包含的内容 |
| --- | --- |
| 歌曲与歌词 | 数据目录 `music` 下的音频、LRC 歌词、封面和音乐索引 |
| 用户音源文件 | 音源脚本、顺序与状态文件，以及上传的用户文件 |
| 歌单与不喜欢快照 | 歌单和不喜欢列表的历史快照，包括已配置的外部快照目录 |
| 用户数据 | 用户设置、播放记录、收藏等其他用户文件 |
| 系统与账户 | 服务器配置、账号列表及数据目录根部的系统 JSON 文件 |

**常规数据备份不包含 `cache`、日志、临时文件、本地备份包和外部自定义音乐目录，也不跟随目录链接。** 程序运行目录下的独立 `music` 目录也不在此范围内。若实际数据目录不是默认 `data`，上述路径以当前数据目录为准。

OpenList 的高级播放缓存可以按用户单独上传 `cache`；它与这里的常规备份不同。系统与账户备份可能包含连接凭据，应保存在自己控制的位置。


### 程序根目录和数据目录如何区分

以下路径相对于程序运行目录，假设使用默认 `DATA_PATH=data`：

| 位置 | 是否进入常规 WebDAV / OpenList 数据备份 |
| --- | --- |
| `cache/` | 不备份，程序根目录缓存 |
| `music/` | 不备份，程序根目录中独立于数据目录的音乐 |
| `data/cache/` | 不备份，数据目录播放缓存 |
| `data/users/用户/cache/` | 不备份，用户目录缓存；其他层级的 cache 同样排除 |
| `data/music/` | 选中并保存“歌曲与歌词”后备份，包括歌曲、已有 LRC、封面和音乐索引 |
| 外部目录，如 `D:/音乐/` | 不备份，需单独保管 |

修改 `DATA_PATH` 后，歌曲范围是 **实际数据目录下的 music**。例如数据目录为 `D:/LXData`，范围就是 `D:/LXData/music`。如果直接把程序运行目录设为数据目录，该位置的 `music/` 就可以被选中备份；不能简单地认为所有“根目录 music”都排除。缓存仍固定排除。

范围选择与服务启用是两件事：保存 WebDAV 列的范围后，还需启用并配置 WebDAV 才会执行云端备份。本地 ZIP 导出和导入也使用这列范围，但不需要启用 WebDAV。OpenList 高级播放缓存使用独立用户规则，可单独处理缓存，不改变常规备份的上述排除范围。

## 配置本地备份

在 **备份管理 → 本地备份** 设置快照数量、本地配置备份和存储路径。

- 本地配置备份默认开启，周期为 24 小时，保留 7 天，默认写入数据目录的 `backups`。
- “锚点时间”默认 `00:00`，表示按服务器本地时间安排周期；留空则从启动或重新设置后按周期计时。
- 配置备份目录留空使用默认位置。相对路径基于数据目录，绝对路径直接使用。
- 快照路径留空使用各用户原有快照目录；设置额外路径后，按用户隔离存放。

在 **备份管理** 中可以导出或导入本地 ZIP，无需开启 WebDAV。ZIP 使用 WebDAV 列已经保存的数据范围；导出前先确认没有漏选需要的内容。

## 使用 WebDAV 备份

1. 在 **备份管理 → 云端备份 → WebDAV** 填写地址、用户名和密码，并启用服务。
2. 设置增量目录和 ZIP 目录，默认分别为 `/lx-sync`、`/lx-sync-backups`。
3. 保存配置，在当前页测试连接。测试只检查已保存目录是否可读取，不创建文件；测试通过不代表上传、删除权限均已验证。
4. 执行一次文件同步或全量 ZIP 备份，查看结果。建议先用少量文件，并实际恢复到独立测试实例确认可用。

增量备份只上传发生变化的文件，默认每 60 分钟检查。ZIP 是所选数据的一份归档，默认每 24 小时检查并在数据变化时创建；手动全量备份可强制创建新归档。

### 两个容易混淆的开关

| 开关 | 关闭时（推荐默认值） | 开启时 |
| --- | --- | --- |
| 本地删除文件时，也删除 WebDAV 增量副本 | 本地删除后，云端仍保留副本 | 下次增量备份删除已跟踪的对应云端文件；ZIP 历史不受影响 |
| 每次启动前，用 WebDAV 备份覆盖本地所选数据 | 需要时手动恢复 | 每次启动先恢复，云端同名文件覆盖本地；恢复完成后才开放服务 |

启动恢复适合明确需要云端作为恢复来源的部署。它不是“只在空目录第一次启动时恢复”，可能覆盖本地较新的数据；失败后进入维护状态，不会自动把本地数据反向上传。

### 历史保留和上传流量

ZIP 默认最多保留 5 份，保留天数默认 0（不限天数）。成功上传后按份数和天数清理，始终保留最新一份；增量目录不受 ZIP 保留策略影响。

上传后检查响应和云端大小，不把整个文件再下载一遍。安全替换需要 WebDAV 服务支持 `MOVE`；若出现 MOVE 错误，应检查服务及代理是否支持该方法。大小一致只表示大小检查通过，不代表内容逐字节相同。

## 使用 OpenList 备份

1. 在 **备份管理 → 云端备份 → OpenList** 填写 OpenList 地址、令牌或账号信息。
2. 根目录填写 **OpenList 中已经挂载的路径**，例如 `/local`。不要填写 Windows 主机路径 `E:\OpenList`；主机路径应在 OpenList 自己的存储挂载中配置。
3. 启用、保存并测试连接，再执行“立即备份并同步缓存”。
4. 在对应记录页查看上传结果。

常规备份保存到根目录的 `_data` 下，并保留相对目录结构。例如根目录为 `/local`，歌曲可能保存在 `/local/_data/music/用户目录/歌曲.mp3`。实际 Windows 磁盘位置由 OpenList 的挂载配置决定。

常规数据备份默认保留本地文件，本地删除不会自动让 `_data` 中的备份跟着删除。高级播放缓存则有独立的按用户规则和存储位置；只有明确选择“上传后删除本地”的规则，才会在严格校验后清理对应缓存。

### “上传完成”和“内容校验”有什么区别

“上传完成”表示上传成功且云端大小检查通过，不表示已比对完整内容。普通备份不会自动下载歌曲验证 SHA-256。记录列表主状态“已备份”与独立的“内容校验”筛选分开；校验筛选匹配当前备份指纹的历史结果。备份版本变化或后台发现云端变化后需重新校验，内部旧 verified 状态不能作为依据。上传后删除和恢复仍会执行各自的自动安全校验。

需要检查内容时，打开 **备份管理 → 记录与校验 → OpenList → 内容校验**：

1. 选择用户、数据类型和范围，先统计预计读取流量。
2. 默认只检查未校验或版本变化的文件；怀疑网盘文件后来损坏时选择全部当前文件。
3. 确认后手动启动，可在后台执行并随时停止。
4. 查看内容一致、不一致、文件缺失或读取失败等结果。校验不会自动覆盖或修复云端文件。

如果存储提供可用的 SHA-256，可直接比较；否则需读取云端正文，会消耗下载流量。旧记录缺少上传指纹时会明确提示，需要重新备份才能建立可比对记录。“上传后删除本地”仍需严格内容校验，因此可能读取云端音频和附件。

## 筛选 OpenList 备份记录

在“备份管理 → 记录与校验”选择 OpenList 文件备份记录。记录区域只有一套筛选：数据类型按钮、用户、存储类别、本地文件状态及排序；点击状态卡筛选对应状态，再次点击取消。状态卡数量随其他条件变化，当前已选条件会显示在面板底部，点击条件标签可单独移除。

搜索支持空格分隔的多个关键词，所有关键词都需命中，可匹配文件名、用户、路径及已有歌曲元数据。“更多条件”提供路径、快照子类型和更新日期范围，日期包含起止当天，按浏览器本地时间解释。多个条件同时生效，没有匹配结果时可逐项移除或重置。筛选和分页复用当前记录；点击“刷新记录”获取最新状态，重新进入记录页也会刷新。不改变备份范围或实际文件。

## 从备份恢复

恢复方向是 **备份 → 当前服务器**，不会上传本地文件，也不会删除本地独有文件。

### WebDAV

1. 在当前实例确认数据目录、配置文件位置和外部快照路径，保存需要恢复的数据类型。
2. 打开 **备份管理 → 数据恢复 → WebDAV** 的恢复窗口，选择增量目录或指定 ZIP。
3. 选择“仅补缺失文件”或“覆盖同名文件”，建议保留恢复前副本。
4. 先预览新增、覆盖、合并索引与跳过数量，再确认恢复。ZIP 预览需下载整个归档，确认后复用，不重复下载；取消或预览过期会清理该临时归档。
5. 完成后重启服务，重新加载用户、歌单、音源与音乐索引。

### OpenList

在 **备份管理 → 数据恢复 → OpenList** 选择当前备份或可用的历史版本，选择范围和覆盖方式，扫描预览后启动。恢复记录可以查看进度，并对支持的任务继续、停止或回退。新实例无需原来的备份数据库，也能从云端数据备份枚举恢复。

### 覆盖规则与失败处理

- **仅补缺失文件**：保留已有文件，只补本地没有的内容。必要的音乐、快照索引按条目合并；普通 JSON 不做字段级合并。
- **覆盖同名文件**：选中范围内的同名文件以备份为准，本地独有文件保留，不是清空整个目录。
- **恢复前副本**：默认保留，可在恢复记录中回退；恢复后又被修改的文件会拒绝自动回退，避免丢失后续改动。确认不需要后可删除记录及副本。

所有需要写入的文件会先下载暂存并校验，再开始替换本地文件。下载失败不会覆盖原文件；写入失败会尝试回滚。旧备份缺少内容指纹时仅检查大小并提示。恢复需要额外磁盘空间存放暂存文件和恢复前副本。

恢复期间进入维护状态；手动恢复完成后需重启，刷新网页不能代替重启。若进程在写入时中断或回滚失败，先在恢复记录中处理回退，再重启恢复正常服务。

## 常见问题

**提示 storage not found？** 检查 OpenList 是否存在且已启用相应挂载，根目录是否与挂载路径一致。连接到 OpenList 不等于已经创建了可写存储。

**为什么 LRC 也上传了？** “歌曲与歌词”包含数据目录 `music` 下已有的 LRC；高级缓存的附件开关只控制独立缓存规则。歌词生成与备份是两个步骤，关闭生成不会删除已有 LRC。

**恢复后看起来没有变化？** 确认恢复来源、数据类型、用户目录和覆盖方式；“仅补缺失”会跳过已有文件。完成后重启服务，再查看结果。

**WebDAV 与 OpenList 会互相同步吗？** 不会。两端各自保存副本，恢复时明确选择一个来源。

配置键与默认值见 [配置说明](./configuration.md)，脚本集成见 [备份接口](../api/reference.md#backup-api)。

### 记录状态与校验结果

记录页主状态表示任务进度：待上传、待下载、传输中、已备份、需处理、失败或已暂停。启用范围中的本地文件大小或修改时间变化会提示待上传，后台按现有周期核对并处理；仅时间变化且内容相同的文件在后台确认后更新基线。服务或范围停用时显示已暂停。播放缓存按上传后删除规则清理本地，不等于删除云端备份。

内容校验独立显示历史结果，不代表实时一致。本地有变化或传输等待期间不在列表突出旧通过标记。后台观察到云端变化后，旧通过结果显示需重新校验，并纳入默认校验范围；要查找同大小、同修改时间的云端内容损坏，应选择所有当前备份文件。刷新记录只检查本地元信息，不下载云端正文。本地、云端变化诊断在详情和高级筛选查看。校验页用户、类型也会限制结果列表。

### 手动检查文件与上次检查时间

在记录页点击“检查文件”，选择本地、云端或两者，以及已选记录、当前筛选结果或当前连接的全部记录。范围只包括记录主文件；绑定附件请使用内容校验入口，历史版本对象不在本次范围。检查存在性、大小、修改时间，不上传、不下载正文、不删除文件，不会生成 SHA-256 内容校验结果。云端逐项请求元信息，允许停止；已完成结果保留。

高级筛选显示当前匹配范围内“已检查 X/Y 项”和最近检查时间，悬停可看最早检查时间；这不是整轮全部成功的证明。每个文件详情有准确时间。本地时间随刷新记录重新检查，手动检查时间另外保留；云端结果按连接与备份版本保存，服务重启后仍可查看。后台检查不保证所有文件同时检查，进程中断的任务需重新启动。

### Subsonic 评分与快照

评分歌单开关仅控制虚拟歌单显示，不启用自动联动。两个联动开关独立控制方向，阈值为 0 时停止联动；联动只补缺失数据，提高或清除评分不删除不喜欢规则，取消不喜欢不删除评分，也不覆盖已有评分。1 星歌单并入不喜欢命中歌曲，保留已有真实评分。

评分快照恢复只替换评分，保留当前歌手和专辑收藏，兼容旧快照格式。评分快照及索引属于备份的「快照」范围；当前 subsonic-meta.json 属于「用户数据」，完整备份请同时选择两项。评分成功但不喜欢解析或写入失败会返回部分成功提示，可重试或手动补同步；两个存储不构成跨文件事务。缓存淘汰的已评分歌曲会尝试重新解析，源不可用时保留评分但暂时无法展示歌曲。

新不喜欢规则按来源去重和匹配；未指定来源时显式作用于全部来源。相同来源、歌曲身份不冲突的重复记录会补齐缺失字段，保留已有有效资料和原始显示名称。新不喜欢记录含 provenance，补全记录含 enrichedBy；评分来源存于 subsonic-meta.json 的 ratingOrigins。手动补同步先预览候选（包含在线缓存），执行时空解析计入失败，资料补全数单独报告。

配置变化不会重算历史数据。提高低分阈值后，手动补齐可增加符合条件的规则；降低阈值、设为0、关闭联动或清除评分不会撤销旧规则。匹配和显示选项仅改变后续过滤/展示结果。Web反向自动补1星仅限带来源和歌曲ID的单首歌曲，歌手和专辑不喜欢不会被误写成歌曲评分。

后台「数据查看 → 不喜欢」按所选用户合并不喜欢规则与不喜欢歌手/专辑库。可筛选类型、添加来源和音乐平台，预览已保存封面、查看规则及完整字段。没有来源记录时显示「来源未记录」，不会推断其来自Web或Subsonic；该页只读，不修改联动或评分。

评分身份迁移与恢复使用事务日志：写入失败回滚，进程中断后在下次评分访问时完成提交。恢复时按当前文件关联整理本地与在线评分，并同步不喜欢原因中的评分 ID，保留手动原因与旧快照。事务日志临时保存于用户 `rating/transaction.json`，完成后移除；不要让多个服务器进程同时写入同一数据目录。
