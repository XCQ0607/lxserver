# V1 与 V2 版本选择

V1 和 V2 都可以播放、缓存和下载歌曲。两者不是简单的新旧版本关系，而是面向不同使用方式的两套存储方案。

## 快速选择

- 需要在 NAS 文件管理器中直接看到下载歌曲，并自行复制、改名、备份或交给媒体工具扫描：选择 **V1**。
- 需要家庭成员或多个账号长期共用服务，并希望用户隔离、分享和存储去重更完善：选择 **V2**。

## 详细对比

| 对比项 | V1 | V2 |
| --- | --- | --- |
| 典型用户 | 个人、单用户、少量用户 | 家庭、多用户、共享 NAS |
| 下载能力 | 支持下载到服务器 | 支持下载到服务器 |
| 文件管理 | `/music` 和 `/cache` 中保留可读文件名，可直接管理源文件 | 通过 Web 界面和数据库管理媒体，不建议手工操作物理文件 |
| 物理存储 | 以用户文件目录为核心 | SQLite 索引与 `DATA_PATH/media` 内容寻址仓库 |
| 重复文件 | 不同用户可能分别保存同一首歌曲 | 相同内容可跨用户复用，减少重复占用 |
| 多用户功能 | 基础用户隔离，部署和目录结构直观 | 用户隔离、管理员音源分享、用户间歌单分享更完整 |
| 外部文件工具 | 适合直接用 NAS、文件管理器和媒体整理工具处理 | 应通过应用功能访问，物理对象使用 SHA-256 哈希命名 |

## V1 适用群体

V1 适合把音乐文件本身作为核心资产的用户。歌曲下载后可以在挂载的 `/music` 目录中直接看到，缓存文件位于 `/cache`。这些文件可以由 NAS 文件管理器、备份软件和其他媒体工具直接处理。

如果你的主要需求是“下载歌曲，并能直接找到和管理源文件”，V1 更合适。

## V2 适用群体

V2 适合多账号共同使用同一台 NAS。它使用 SQLite 保存用户、媒体和归属关系，并将音频存入 `DATA_PATH/media` 下的内容寻址仓库。同一音频内容可以被多个用户引用，而不必重复保存物理文件。

V2 仍然支持下载歌曲，但下载区和缓存区是逻辑分类；底层物理文件是内部媒体对象，不适合作为普通音乐目录手工改名或移动。

## 部署与迁移限制

V1 与 V2 的持久化目录和数据结构不兼容：

- 不要让两个版本挂载或共用同一个数据目录。
- V2 不是 V1 的原地升级版本，不能直接复用 V1 数据启动。
- 从 V1 转到 V2 前，应先备份歌单和需要保留的数据，再按 V2 文档全新部署并导入。
- 需要继续直接管理现有音乐文件时，保留 V1 通常更稳妥。
